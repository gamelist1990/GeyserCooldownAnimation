# Geyser Cooldown Crossplay Weapons

剣・斧・メイスのスイングと持ち方はユーザー指定のBlurry's Crossplay Animations 2.0を基準にしています。
素手・トライデント・ツルハシ・シャベルにもクールダウンの腕下げを適用します。
ツルハシ・シャベルは全材質で剣と同じスイングを使用し、スイング後の回復も剣と同じ姿勢です。
素手・トライデントは標準のスイングに回復動作を重ねます。hoeは対象外です。

## スイングとクールダウンの分離
サーバーのanimation.player.cooldown_20ms_1～500は、腕を動かさず、
duration（20ms刻み）、通知時刻、再生要求だけをplayer変数へ渡します。
剣・斧・メイス・ツルハシ・シャベルはvariable.attack_time > 0の間、回復の上下動を再生しません。
スイングが終わると各アイテムに対応した回復アニメーションへ移ります。
剣は下げ幅10、斧・メイスは12。剣・斧は参照元のcatmullrom、メイスは線形です。
連打で再びスイングが始まると回復を中断して待機状態へ戻ります。

通知からスイング終了までの経過時間を差し引き、残り時間で復帰します。
通知の期限を過ぎたら待機・回復を終了し、期限切れの腕下げは再生しません。
素手・トライデントはスイング終了を待たず、通知時刻からの経過時間で復帰します。
参考パック Cooldown Animation(OPTIONAL)V1.4.0 に合わせ、素手・トライデントは
0から下げ幅20まで原則0.125秒で下げ、その後サーバー通知の期限までに0へ戻します。
通知の残り時間が0.25秒未満の場合は、下げ・戻しにそれぞれ半分の時間を使います。
投擲中は追加の回復動作を抑えます。一人称・非VRのみが対象です。
トライデントを斧のスイングに割り当てず、槍は標準の専用controllerを使用します。
槍は取り出すときの標準swap-itemアニメーションを維持し、攻撃・持ち替えの通知による追加の腕下げは適用しません。
Blurry単体の剣0.3秒・斧1.0417秒・メイス2秒という固定時間は使わないため、
サーバー通知時間を優先した分の違いは残ります。

## attachablesと秒数
ツルハシ・シャベル・槍は木・石・銅・鉄・金・ダイヤ・ネザライトの各材質にattachableを用意しています。
ツルハシ・シャベルは参考パックのtextureと表示定義を使用します。
槍・トライデントはMojang bedrock-samplesのgeometry・使用アニメーション・controllerを専用名で同梱しています。
槍は所有プレイヤーの標準の使用・攻撃rotationに追従し、トライデントはチャージ・激流の表示を維持します。
メイスは既存のattachableと持ち方を維持します。
剣・斧・メイス・ツルハシ・シャベルの共通item geometryは参照元のrightitemと座標を維持し、
動的bindingを追加しません。槍・トライデントは公式geometryの武器slot bindingを使用します。

秒数は固定アイテム表から選ばず、Geyserの実効攻撃速度を使用します。
基本時間は `max(millisecondsPerTick / 50, 1) / attackSpeed` 秒です。
観測までの遅れを差し引き、残り時間を20ms単位で切り上げて通知します（最大10秒）。
20TPS・観測遅延なしの例：速度4なら0.25秒を0.26秒、1.2なら約0.833秒を0.84秒、0.6なら約1.667秒を1.68秒で通知します。
参考パックの固定値（素手0.25・剣0.65・ツルハシ0.90・メイス1.65秒等）は時間計算に使いません。
20msは通知する残り時間の精度です。新しい開始時刻を10ms間隔で監視し、変化がある時だけ送信します。
腕の補間はBedrockの描画フレームごとに実行し、20msごとにパケットを送り続ける方式ではありません。
切り上げによる誤差は20ms未満です。旧50ms用の識別子と未使用の固定秒数profileは生成しません。
パケット配送遅延は補正していないため、サーバーと表示の完全な同時刻一致は保証しません。

## 重複と送信
同じsequenceの重複通知だけを抑制します。45msの間隔制限はありません。
Geyserの開始時刻が変われば、45ms以内でも新しい時間通知を送信します。
通知は動きを直接再開しないため、連打で腕下げアニメーションが積み重なりません。
packetのruntime controllerはgeyser_cooldown_timingという専用名です。
